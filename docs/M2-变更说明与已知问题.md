## 5. 本批关键结论（长期）

1. **稳态 CPU 突发的根因与量化（K-13 收口）**：打点归因证明稳态突发**全部来自周期性唤醒**——看门狗心跳、全屏兜底轮询、（旧）1Hz 采样器；且每次唤醒无论实际工作量多小，进程 CPU 记账都会计一个 **15.6ms 刻度**（Windows 记账粒度）。修复三件套（枚举移后台 / 全屏退避 / 心跳 5s）后稳态 0.417%；**对照实验**关闭看门狗 = 0.104% ≤0.3%。结论：**8.1 的 ≤0.3% 与 AC-11 的 UI 心跳存在内在张力**（5s 心跳 ≈ 0.156~0.312% 记账），用户可用 `behavior.watchdogEnabled=false` 取舍；指标口径建议提交产品确认。
2. **去 WinForms 实测收益 ~20MB**：工作集 218 → 191~196MB；发布目录不再含 `System.Windows.Forms.*` / `System.Drawing.*` DLL。
3. **序数图标资源的封送坑**：`LoadImageW` 加载 `IDI_APPLICATION` 必须以 `MAKEINTRESOURCE`（数值 IntPtr）传名，封送成字符串会被按资源名查找并报 `ERROR_RESOURCE_TYPE_NOT_FOUND(1813)`。
4. **锁屏对自动化验证的影响**：锁屏窗口是前台全屏窗口，光标合成输入全部失效——交互冒烟失败时先查前台是否锁屏（`Windows.UI.Core.CoreWindow`），再怀疑代码回归。
5. **未归因大突发**：观察到 562ms/s 的窗口无对应指标（疑似 GC / 驱动），打点框架后续可加 GC 计数（`GC.CollectionCount`）进一步定位。
