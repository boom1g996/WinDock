## 5. 本批关键结论（长期）

1. **自动化必须与目标进程同坐标系**：Windows 的 125% 缩放会让 DPI 不感知进程看到「虚拟桌面」（1792×1120），而 PerMonitorV2 应用用物理像素（2240×1400）。凡是用枚举矩形算点击点的脚本，先 `SetProcessDpiAwareness(2)`，否则一律偏移。**且不要用 `Visual.PointToScreen` 定位**：本机实测它对 Dock 窗口返回的原点与 `GetWindowRect` 相差 (164, 247)，命中判定走的是 HWND 真实矩形——用 `GetWindowRect + TransformToAncestor` 才与真实点击对齐。
2. **心跳间隔不能贴着急救阈值**：阈值/2 只剩 1 次丢帧余量，交互期一次 5s 级调度延迟就触发假阳性；阈值/3（3 帧/窗口）才稳。代价是 +3 次 UI 唤醒/30s ≈ +0.15% CPU，已计入 8.1 复核表。
3. **假阳性比漏判更伤**：误判会写出恢复事件，下次启动弹「上次异常退出」，属于用户可见的错误信息。因此超时判定必须打印「已收帧数 / 距最后一帧 / 宿主是否存活」，把假阳性和真卡死分开。
4. **自包含单文件可行**：运行时包必须联网 restore，但只影响**发布**这一步——`src/NuGet.config` 保持清空包源（日常构建仍完全离线），发布时用 `-p:RestoreSources` 单点注入即可，两者不冲突。
5. **长稳实证要用可续采的采样器**：一次性 `--sample-seconds 86400` 中途被打断就全废；`stability_m1.py` 逐行 flush + `--summary` 汇总，崩溃即停并保留证据（不自动重启掩盖问题）。
