## 2. 变更说明

### 2.1 WD-001 工程骨架与构建链
新增 `WinDock.sln`（传统 sln 格式）、`Directory.Build.props`（`net10.0-windows`、`UseWPF=true`、`Nullable=enable`、`TreatWarningsAsErrors=true`）、`NuGet.config`（清空包源，零外部依赖）、三个 csproj、`app.manifest`（PerMonitorV2 + longPathAware + asInvoker）。

### 2.2 WD-002 配置、日志与本地化
`ConfigService` 支持 camelCase JSON、`schemaVersion`、未知字段忽略、越界夹紧、非法枚举回退、损坏回退默认并备份 `config.corrupt.*.json`、临时文件 + `File.Replace` 原子写、`FileSystemWatcher` 120ms 去抖热更新。`LogService` 落到 `%LocalAppData%\WinDock\logs`，保留 7 天，用户名路径脱敏。中英 `.resx` 由 `Loc.Instance.T(key)` 统一读取。

### 2.3 WD-003~005 系统互操作三件套
`TaskbarInterop` 用 `GetWindowRect` **动态推断原生任务栏边缘**（M0 实测本机在顶部 `[0,0,1792,48]`），快照持久化用于崩溃后恢复；默认模式 C 下组合根**不调用 `Hide()`**。`WindowEnumerator` 用 `SetWinEventHook` 事件驱动、`DWMWA_CLOAKED` + `WS_EX_TOOLWINDOW` + shell class 过滤、按进程聚合。`IconService` 优先 `PrivateExtractIconsW`，回退 `ExtractIconEx` / `SHGetFileInfo` / 自绘问号，图标内存缓存并冻结。

### 2.4 WD-006~009 Dock 渲染、动画与交互
无边框分层胶囊（圆角 / 描边 / 半透明，Acrylic 尽力而为）、固定区 + 分隔符 + 运行区 + 「+」空态、4px macOS 运行指示点。`AnimationEngine` 单一 `CompositionTarget.Rendering` 时间轴、邻域余弦/高斯/线性衰减、底边对齐与水平位移补偿、空闲取消订阅、尊重系统「减少动态效果」。点击行为覆盖启动 / 激活（含 `AttachThreadInput` 前台锁重试 3 次）/ `Shift` 新建窗口 / `Ctrl` 或右键菜单 / 中键二次确认关闭全部；右键菜单含窗口列表、固定移除、资源管理器定位、设置、隐藏 Dock。

### 2.5 WD-010~012 设置、托盘与异常兜底
独立设置进程提供图标尺寸 / 间距 / 圆角 / 透明度 / 放大倍率 Slider + 开机自启 + 实时预览，150ms 去抖保存。托盘菜单含显示隐藏、恢复原生任务栏、设置、退出。`StartupRegistry` 只写 HKCU Run 键。`App.xaml.cs` 捕获 Dispatcher / AppDomain / TaskScheduler 三类未处理异常，写日志并尝试恢复任务栏，禁止系统崩溃框。

### 2.6 WD-013 性能收敛（本轮重点）
初次实机冒烟 CPU 21.172%、内存 269.02MB，定位到 4 层叠加根因并全部修复：

| # | 根因 | 修复 |
| --- | --- | --- |
| P1 | 动画目标非 1 时被判为「未收敛」，hover 静止时 60FPS 永久空转 | 收敛判定改为「当前值 ≈ 目标值」，不再以目标是否为 1 判断 |
| P2 | `EnsureRunning()` 无条件订阅渲染，`ClearHover()` 每次白跑一帧 | 新增 `IsSettled()` 短路，目标已达成时完全不订阅 |
| P3 | 窗口集合签名包含 `window.Title`，浏览器 / IM 标题变化即触发事件 | 签名改为「组 Key + 显示名 + 句柄 + 前台/最小化位」，标题仍逐次刷新到数据模型但不触发 UI 重建 |
| P4 | `RebuildIcons()` 每次事件清空 `IconsPanel` 全量重建；`IconService.CacheKey()` 每项都做 `GetLastWriteTimeUtc` | 拆成 `BuildItems` / `UpdateIcons` / `RenderIcons`：结构未变只增量 `Bind()`；时间戳缓存 30s；指示点画刷改为冻结静态对象 |

配套修复：`SetWinEventHook` 由宽区间改三段窄订阅、250ms 去抖、进程信息缓存、窗口签名变化检测。

## 5. 内存构成诊断（2026-11-09 实机）

启动 6 秒时采样：WorkingSet **234.35MB** / Private **161.76MB** / 模块 161 个 / 线程 68 / 句柄 612；30 秒稳态 WorkingSet 回落到 198.79MB。

| 模块 | 映射大小 | 说明 |
| --- | --- | --- |
| `igc64.dll` | 81.15 MB | Intel 显卡 Shader 编译器（WPF D3D 硬件渲染加载） |
| `media_bin_64.dll` | 32.45 MB | Intel 媒体驱动 |
| `igd9trinity64.dll` | 25.58 MB | Intel D3D9 用户态驱动 |
| `igd9dxva64.dll` | 23.05 MB | Intel DXVA 驱动 |
| `System.Private.CoreLib.dll` | 15.28 MB | .NET 运行时 |
| `PresentationFramework.dll` | 15.08 MB | WPF |
| `System.Windows.Forms.dll` | 13.07 MB | 托盘 NotifyIcon 引入 |
| `PresentationCore.dll` | 7.93 MB | WPF |
| WinForms / GDI+ 系合计 | ≈ 20 MB | 含 Primitives、Common、gdiplus、资源 |

结论：约 162MB 的模块映射来自 **Intel 显卡用户态驱动**，是 WPF 硬件加速的必然开销，属于共享 DLL 映射；去掉 WinForms 托盘约可省 20MB，仍不足以降到 120MB。这是需求指标与本技术栈 + 本机 GPU 环境的结构性冲突，需作为产品级决策处理（见 K-01）。

4. WD-014 缩略图预览、WD-015 自动隐藏与全屏检测、WD-016 拖拽排序（M2 P0 主体）。
