## 2. 关键发现（会改变设计）

1. **任务栏在顶部，不是底部。** 文档中「屏幕底部 2px 热区」「滑出方向 = 高度 + 8」等描述均按底部写死。实测本机两块屏的任务栏都在顶部。
   → `TaskbarInterop` 必须通过 `GetWindowRect(Shell_TrayWnd)` **动态推断边缘**，记录原始 rect 用于恢复；`DockRenderer` 的 Dock 位置（底部/左/右）与原生任务栏边缘解耦，不得互相假设。
2. **Build 26200 超出兼容矩阵。** 隐藏 `Shell_TrayWnd` 属非官方 API，微软在 24H2/25H2 已多次改动任务栏窗口树。
   → M1 必须把「隐藏 + 恢复」做成可独立验证的原子操作，并默认**不启用**（见 §4 结论）。
3. **副屏是负坐标且尺寸与主屏不同。** 任何用 `SM_CXSCREEN` 或假定主屏从 `(0,0)` 起、所有屏等高的布局算法都会错位。
   → 统一用 `EnumDisplayMonitors` 返回的绝对 rect + `GetDpiForMonitor`。
4. ** cloaked 窗口占可见窗口的 48%（12/25）。** 不做 `DWMWA_CLOAKED` 过滤，Dock 运行区会出现大量空图标。
5. **构建链已从零打通。** 初始无 .NET SDK / VS；现已安装 .NET SDK 10.0.403 并成功编译 WPF 项目（§7）。但 §3 的 API 结论仍只基于操作系统导出实测，**Dock 产品代码尚未编写**，无边框窗口 Acrylic、DWM 缩略图等需到 M1 实机验证。

## 3. 第 4.3 表逐项结论

| # | 能力 | 结论 | 实测依据 | 落地方式 / 限制 |
| --- | --- | --- | --- | --- |
| 1 | 隐藏原生任务栏 | **降级** | `Shell_TrayWnd` / `Shell_SecondaryTrayWnd` 均存在且可 `GetWindowRect`；`SetWindowPos` 导出存在 | 无官方 API。只做「移出屏幕 + 记录原 rect」，禁止设 0 高度（会破坏 Explorer 布局）；监听 `TaskbarCreated` 重应用；默认模式 C，模式 A 需用户显式开启；**M0 未做写入验证** |
| 2 | 屏幕预留空间 `SHAppBarMessage` | **降级（建议不做）** | `SHAppBarMessage` 导出存在；`ABM_GETSTATE` 实测返回 0 | Dock 是悬浮胶囊，本就不应占工作区；注册 AppBar 会与原生任务栏抢同一边并改变所有最大化窗口尺寸。**M1 不注册 AppBar** |
| 3 | 枚举窗口 | **可行** | `EnumWindows` 实测 419→25→7；`DwmGetWindowAttribute(DWMWA_CLOAKED)` 成功剔除 12 个 | 用 `SetWinEventHook` 事件驱动 + 启动全量扫描，禁止轮询；UWP 需处理 `ApplicationFrameHost` 宿主（本机未出现，待补测） |
| 4 | 实时缩略图 | **可行（带降级）** | `DwmRegisterThumbnail` / `DwmUpdateThumbnailProperties` / `DwmUnregisterThumbnail` / `DwmQueryThumbnailSourceSize` 全部导出存在；DWM 合成开启 | 最小化窗口 DWM 不刷新 → 按文档 6.402 用最后快照 + 半透明遮罩；最多 6 个、关闭即注销。**M0 未做实际注册验证** |
| 5 | 高清图标 | **可行（带降级）** | `SHCreateItemFromParsingName` / `SHGetFileInfoW` / `CoCreateInstance` 导出存在 | `IShellItemImageFactory::GetImage` 取 256px；UWP 走 AUMID→Package Logo，失败回退默认图标；<48px 源图标按文档标记提示 |
| 6 | 前台 / 全屏检测 | **可行（带降级）** | `SHQueryUserNotificationState` 实测 hr=0；`GetForegroundWindow` 导出存在 | QUNS 无法覆盖全部 UWP 全屏 → 补「窗口 rect == 屏幕 rect 且非 Dock 自身」判定；独占 3D 全屏另判 `QUNS_RUNNING_D3D_FULL_SCREEN` |
| 7 | 全局鼠标钩子 | **降级** | `SetWindowsHookExW` / `UnhookWindowsHookEx` 导出存在 | 优先用「边缘 2px 隐形热区窗口 + 鼠标位置检查」，**不装全局钩子**；钩子仅作为 P2 可选项且必须可卸载（文档 8.6） |
| 8 | 开机自启 | **可行** | 当前会话非管理员 | 用 `HKCU\...\Run`（仅用户项，符合 4.4）；禁止任务计划程序提权启动，否则无法与普通窗口交互 |
| 9 | 管理员窗口交互 | **不可行** | 当前进程非管理员 | UIPI 限制，v1 不绕过；UI 明示，保留「以管理员重启 Dock」为后续选项 |
| 10 | 系统背板 Acrylic/Mica | **降级** | `DwmSetWindowAttribute` 导出存在，`DWMWA_SYSTEMBACKDROP_TYPE` 查询 hr=0；Build 26200 支持 | 无边框分层窗口上 Mica 观感与可控性差；v1 默认走 `DwmSetWindowAttribute` 系统 Acrylic + 自绘半透明色层，圆角/描边/倒影全部自绘；RDP / 无 DWM 时回退纯色 |
| 11 | 多显示器 / PerMonitorV2 | **可行** | 2 屏实测成功，`GetDpiForMonitor` hr=0；`GetDpiForWindow` 导出存在 | 必须按显示器绝对 rect 布局；热插拔监听 `WM_DISPLAYCHANGE` |
| 12 | Win 键接管 | **不可行（v1 不做）** | — | 全局键盘钩子风险高，且与文档 0.2「其余一律 Windows 化」、2.2 非目标冲突。文档 6.13/6.2 未定义任何 Win 键行为需求 |
| 13 | 最小化动画全局劫持 | **不可行** | — | 文档 6.9 已明确：无公开 API，强行实现需注入，违反「不注入」原则。按文档实现 Dock 侧 300ms 反馈动效 |
| 14 | 系统托盘完整复刻 | **不可行** | — | 文档 6.12 明确不做；模式 A 下托盘缺失，用共存模式 B 兜底 |
| 15 | 崩溃恢复 / 看门狗 | **可行** | 普通权限会话，无提权需求 | 独立 Watchdog 进程 + 心跳；主进程 `UnhandledException` 与进程退出双路径恢复任务栏 |

**API 导出复核**：探针检查了 5 个 DLL 共 41 个入口点，**全部存在**。初版探针把 `GetDpiForSystem` 错归到 `shcore.dll`（报告 false），已修正为 `user32.dll` 并复测为 true —— 这是一次探测脚本归类错误，不是系统能力缺失。
