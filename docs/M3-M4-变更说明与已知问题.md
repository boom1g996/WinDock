### 6.3 顺带修掉的自检缺陷

`--selftest` 分支原先排在**单实例互斥之后**：Dock 正在运行时执行 `--selftest` 会被互斥分支直接 `Shutdown(0)`，一条断言都没跑却返回 0，结果文件停留在上一版，形成「自检假通过」。现已把自检分支移到互斥之前，并给结果文件写入加了失败日志与独立退出码（`0` 全通过 / `1` 有失败 / `2` 结果落盘失败）。

### 6.4 实机崩溃修复（19:20）

首次用新构建重启 Dock 时整窗崩溃，日志为 `InvalidOperationException: 无法冻结此 Freezable` @ `MainWindow.UpdateReflection`：

- **根因**：FR-101 倒影用的是 `VisualBrush(IconsPanel)`。**绑定到活 Visual 的 Brush 永远 `CanFreeze=false`**，代码里为省内存调的 `brush.Freeze()` 在 `Capsule.SizeChanged` 里抛异常；该回调是布局回调，异常直接冒到 Dispatcher → 整窗崩溃。预设 `macosDark/macosLight` 默认开启倒影，所以只要应用过预设就必崩。
- **修复**：① 去掉 `Freeze()`（不冻结反而让倒影随图标变化自动更新）；② 给 `SizeChanged` 回调加 try/catch + WARN，装饰性功能不得拖垮主条；③ 自检新增「VisualBrush 绑定活 Visual 时不可冻结」断言锁定该不变量。
- **教训**：`Freezable` 系（Brush/Transform/Effect）在「绑定活对象」时都不能冻结；给布局/渲染回调挂逻辑一律兜底 try/catch。

## 8. 质感改造（毛玻璃引擎重做）

用户反馈「看不到透明的毛玻璃效果」「图标还是太模糊」，排查后确认是**两个独立根因叠加**，而非参数没调好。

### 8.1 根因

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 完全看不到模糊，只有一块半透明灰板 | `DwmExtendFrameIntoClientArea(-1)` **本身不产生任何模糊**，它只负责让客户区可以透出 DWM 的 backdrop。此前除 `mica` 外的所有模式都把 `DWMWA_SYSTEMBACKDROP_TYPE` 设为 `DWMSBT_NONE`，等于「透明但没模糊」，透出来的是未处理的桌面（多数机器退化成黑/灰）。 |
| 2 | 玻璃更没有存在感，像"图标浮在桌面上" | 用户配置里 `appearance.opacity = 0`。旧实现 `tintAlpha = opacity × blurFactor` 直接得 0，胶囊底色完全透明。 |
| 3 | 图标糊 | `RequestedIconPx()` **漏乘 DPI**。125% 缩放下 48px 图标实占 60 物理像素、放大态需 105，而位图只按 92px 提取后再拉伸。 |

### 8.2 为什么不用 DWM 的 Acrylic / Mica

`DWMWA_SYSTEMBACKDROP_TYPE` 作用于**整个窗口矩形**。而 Dock 窗口为了容纳图标放大溢出与阴影，比胶囊大一圈（左右各约 28px、上方约 48px）。一旦打开系统 backdrop：

- 胶囊外侧会露出一整块**矩形雾**，形状无法裁剪（DWM 只能裁 8px 圆角）；
- 窗口矩形与胶囊形状不可能一致（除非砍掉放大溢出，或重构为双窗口）。

所以改为**自绘毛玻璃**：抓胶囊背后的屏幕画面 → 高斯模糊 → 当作胶囊的 `Background`。模糊严格落在胶囊形状内，放大溢出、倒影、阴影全部不受影响，`blurLevel` 也从"改底色浓度"变成**真正控制高斯半径**（12 / 22 / 34 px）。

### 8.3 抓屏"不截到自己"的四条路径（都实机验证过）

| 方案 | 结果 |
| --- | --- |
| `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` | 设置后**同进程**的 `BitBlt` 直接 `ERROR_ACCESS_DENIED(5)` —— Win10 2004+ 的截屏保护是进程级的 |
| `DwmSetWindowAttribute(DWMWA_CLOAKED, 1)` | `E_INVALIDARG`，该属性只读 |
| `PrintWindow(GetDesktopWindow(), PW_RENDERFULLCONTENT)` | 返回 0 且内容全黑 |
| 临时 `WS_EX_LAYERED` + `SetLayeredWindowAttributes(alpha=0)` | WPF 的 HwndSource 自己接管窗口样式，改不动，随后报 `ERROR_INVALID_PARAMETER(87)` |

**最终方案**：`ShowWindow(SW_HIDE)` → `DwmFlush` → `BitBlt` → `ShowWindow(SW_SHOWNOACTIVATE)`。
选它的理由：HWND 级隐藏**不动 WPF 的 `Visibility`**，因此不会触发 K-22 的 `SizeToContent` 2×2 收缩与重排；恢复用 `SW_SHOWNOACTIVATE` 不抢焦点。
窗口本来就隐藏（自动隐藏态，默认配置）时**什么都不做**，直接抓 —— 这也是常见路径。

### 8.4 顺带修掉的真 bug

| 问题 | 根因 | 修法 |
| --- | --- | --- |
| **按 Win+D 回桌面后 Dock 永久消失、热区失效，鼠标怎么划都唤不回来** | 桌面窗口 `Progman` 铺满整屏且没有 `WS_MAXIMIZE`，被 `ForegroundCoversMonitor` 判成"独占全屏应用" → Dock 隐藏 + 热区禁用 | 全屏判定排除 shell 自身的类名（`Progman` / `WorkerW` / `Shell_TrayWnd` / `Shell_SecondaryTrayWnd` / 托盘溢出面板 等），并加 `IsWindowVisible` 判据 |
| `fullScreenHide=false` 后仍打「进入全屏/演示态」 | 检测器无条件打日志（实际未隐藏），日志误导排查 | 保留日志但补 shell 类名排除，误判本身消失 |
| 锁屏 / UAC 期间反复抓屏失败并把玻璃永久停用 | 失败原因是环境不是方案 | 抓屏前 `OpenInputDesktop` 判可交互桌面，安全桌面直接跳过**且不计入失败次数**；鼠标进入 Dock 时自愈重试 |

### 8.5 视觉细节

| 项 | 改动 |
| --- | --- |
| 磨砂颗粒 | 64×64 随机灰度 + 低 alpha 平铺（固定种子），`Opacity=0.06`。大面积半透明不加颗粒会像"塑料板" |
| 顶部高光 | 1px 白色渐变从**底部**移到**顶部**（光源在上，符合 macOS），左右内缩 14px 避免顶到圆角露断头线 |
| tint 下限 | `0.18 + opacity × 0.46 × blurFactor`，夹在 `[0.18, 0.78]`。opacity=0 也有可辨识的玻璃底，不再退化成"图标悬浮" |
| 深/浅色主题 | 读 HKCU `SystemUsesLightTheme`：深色用 `#0E1016`、浅色用 `#F2F5FA` |
| 图标底色 | 去掉 `IconFrame` 的 `#14FFFFFF` 底与 `Margin=2` —— 非圆角图标会多一圈淡方块，和毛玻璃叠起来显脏 |
| 图标提取 | `IconSize × MagnifyScale × DPI + 8`，吸附到系统档位 32/48/64/128/256（`PrivateExtractIcons` 收到任意尺寸也是取最近档再缩放，直接要整档更清晰） |

### 8.6 已知限制

| 项 | 说明 |
| --- | --- |
| 锁屏 / UAC 安全桌面 | 不抓屏，胶囊停在兜底纯色；解锁后鼠标进入 Dock 即自愈 |
| 全屏独占 / D3D 游戏 | `BitBlt` 失败，同上回退；连续失败 3 次停用直到下次配置变更 |
| 背景实时性 | 玻璃在「唤出 / 位置变化 / 尺寸变化 / 配置变更」时重抓，不是逐帧。背后窗口移动时 Dock 背景不会实时跟随（macOS 是实时的）。抓屏频率刻意压低，避免违反空闲 CPU ≤0.3% |
| 抓屏开销 | 单次约 1–3ms（区域仅胶囊外扩 ~26px），加 `DwmFlush` 两次约 2 帧。仅发生在上述时机 |
| 隐私 | 抓屏结果只在内存中作为背景位图，不落盘、不外发（需求 8.6） |

## 9. 窗口尺寸失控修复（"显示区域很窄 / 点击区是长方形"）

### 9.1 现象

实机体验反馈两条，看起来是两个问题，实际是**同一个 bug**：

> 显示区域很窄，我以为它是按屏幕宽度显示的；可点击区域应该限制在对应的图标上，不应该是一个长方形区域。

### 9.2 根因（`SizeToContent` 在折叠后复用旧测量值）

窗口原来是 `SizeToContent="WidthAndHeight"`，尺寸由 WPF 按内容自动算。问题出在
**自动隐藏把 `Visibility` 设成 `Collapsed`**（K-22 记录过：折叠时 HWND 会被收缩）。
恢复可见时，WPF 复用的却是**上一次有效测量缓存**——实测停在"只有 + 按钮"时的大小：

| 指标 | 实测值（修复前） | 应有值 |
| --- | --- | --- |
| 窗口 HWND | 170 × 198 px（136 × 158 DIP） | 840 × 251 px（672 × 201 DIP） |
| 图标横向跨度 | 588 px | 588 px |
| 结论 | 7 个图标里只有约 1.7 个落在窗口内 | 全部落在窗口内 |

超出窗口矩形的图标被 DWM 裁掉，于是：

- **看得见的玻璃**只有中间一小条 → "显示区域很窄"；
- **能点/能挡住的**是那块 136×158 的长方形 → "可点击区域是长方形"；
- 又因为 `Position()` 用 `ActualWidth` 居中，宽 136 的窗口在屏中央，图标却向右铺 588px → 整条 Dock 明显偏右。

### 9.3 修法

1. 移除 `SizeToContent`，改为**显式宽高**：`SyncWindowSize()` 用
   `Root.Measure(∞)` 实测内容尺寸 + `Root.Margin` 留白，直接写 `Width`/`Height`。
   调用点：构造末尾、`OnLoaded`、`Position()` 开头（每次结构变化后都会走）、
   `Capsule.SizeChanged`（尺寸变化后异步重新居中）。
2. `Position()` / `HiddenDistance` 改用 `Width`/`Height`（权威值），不再依赖可能滞后的 `ActualWidth`。
3. 显式尺寸不依赖 `Visibility`，因此 **K-22 的 2×2 收缩一并根治**。

### 9.4 踩过的坑

| 坑 | 说明 |
| --- | --- |
| `Math.Abs(Width - w) > 0.4` 永不成立 | `Window.Width` 默认 `NaN`，`NaN` 参与的任何比较都是 false → 第一次赋值被跳过，窗口永远停在首帧尺寸。必须先判 `double.IsNaN` |
| 旧进程残留导致"改了没效果" | 单实例互斥让新进程直接退出，`--dump-layout` 被**旧 dll 的常驻实例**响应，日志格式还是旧的。排查前先 `taskkill` 干净 |

### 9.5 顺带修掉的真 bug：`fullScreenHide=false` 不生效

`AutoHideController` 只在 `OnFullScreenChanged` 里判配置开关，但 `_inFullScreen` 已经被置 true；
`ApplyConfig` 的恢复分支写的是 `if (!_enabled && IsHidden && !_inFullScreen) Show()`，
于是**关掉自动隐藏也显示不出来**（全屏态一直拦着）。现在 `_inFullScreen = full && _fullScreenHide`，
`ApplyConfig` 里也按配置重算，开关语义才真正一致。

### 9.6 验证方式（本次无法目视，已用数据代替）

锁屏状态下 `QUNS=1`（NOT_PRESENT），BitBlt 只能抓到锁屏前的桌面残留、`PrintWindow` 全黑，
两条截图路径都不可用。改用 `--dump-layout` 输出的尺寸链路自证：

```
w=672.0 h=200.8 root=(621.6x158.4) cap=(570.4x116.0) panel=(548.8x60.8) children=7
hwnd=(700,1139,1540,1390)  图标 x=[827..1415] 全部落在窗口内
```

`672 = 621.6 + 25.2×2`，`621.6 = 570.4 + 25.2×2`，`570.4 = 548.8 + 10×2 + 1×2`，
`548.8 = 7×79 − 4` —— 四层逐级自洽，说明尺寸链路上没有任何一层再"没长"。

### 9.7 仍未闭环

- 图标之间 18px 的间距、胶囊内 10px 的 padding 仍属于窗口命中区，点击不会穿透到下层窗口。
  真正的"完全穿透"需要改成 per-pixel alpha 的分层窗口（`AllowsTransparency=true`），
  但会失去 DWM 合成路径、直接影响 AC-21（≥55 FPS）与 AC-20（空闲 CPU ≤0.3%），暂不做。
- 玻璃的 hover 放大是 `RenderTransform`，不改变布局尺寸；放大后图标边缘超出控件命中框，
  极端情况下会出现"贴边抖动"。属交互时序问题，排在下一轮。

## 10. 实机体验反馈集中修复（2026-11-11）

用户提供三张实机截图，反馈四件事：图标有空白块、和 macOS 差距大、预览弹窗"放上去很卡很慢"、
从预览弹窗打开的窗口变成 Win 小窗。

### 10.1 致命 bug：启动 0.3s 就抛未处理异常（图标整块消失的根因）

日志里当天 **88 次未处理异常**，栈全部指向同一行：

```
System.InvalidCastException: Specified cast is not valid.
   at WinDock.MainWindow.CreateSystemGlyph(String kind)
   at WinDock.MainWindow.SystemItem(...) → AppendSystemArea → BuildItems → RebuildIcons
```

`.NET 10` 的 `Geometry.Parse(string)` 返回的是**已冻结的 `StreamGeometry`**，
而代码写的是 `(PathGeometry)Geometry.Parse(data)` —— 强转直接抛异常。
`BuildItems` 在异常处中断，于是：

- 整条 Dock 的重建半途而废 → 界面残留部分图标 / 空白格，随后进程退出；
- 用户看到的就是"图标变成了白色空块、Dock 时不时消失"。

修法：不再强转，直接使用 `Geometry`；同时给系统区字形加一层半透明深色描边。
原来字形是纯白 `#F2F4F8`，在浅色桌面的胶囊上（几乎白色的毛玻璃）等于隐形，
截图里"回收站 / 任务视图 / 显示桌面"就是三团白斑，正是用户圈出来的白块。

### 10.2 从预览面板打开的窗口变成"小窗"（窗口状态被重置）

旧实现：

```csharp
ShowWindow(handle, window.IsMinimized ? SW_RESTORE : SW_SHOWNORMAL);
```

`SW_SHOWNORMAL` 的语义是"**若窗口已最大化则先还原成普通大小**"，
所以点一个正最大化的窗口反而把它缩了，用户看到的就是"一律以 Win 小窗打开"。

新实现 `RestorePreviousState()`：先 `GetWindowPlacement` 记下最小化前的状态
（`showCmd == SW_SHOWMAXIMIZED` 或 `flags & WPF_RESTORETOMAXIMIZED`），
然后**只在需要时**动 `ShowWindow`：

| 场景 | 处理 |
| --- | --- |
| 已最小化（原来是最大化） | `SW_RESTORE`，若仍未最大化再补 `SW_MAXIMIZE` |
| 已最小化（原来是普通） | `SW_RESTORE` |
| 已可见且最大化 | **完全不调用** `ShowWindow`，只抢前台 |
| 已可见普通 | 同上 |

自检里用**真实窗口**跑两种场景（`84/84` 之一、之二）：
最大化→最小化→唤出后 `IsZoomed=True`；普通→最小化→唤出后 `IsZoomed=False`。

### 10.3 预览面板"卡、慢"

两个原因叠加：

1. **每次悬停都 `new PreviewWindow`**：BAML 解析 + 建 HWND + DWM 注册，首次 60~150ms；
2. `SizeToContent` + `Dispatcher.BeginInvoke(Loaded)` 里才定位，面板会先在错误位置出现再跳。

改法：

- 面板实例**常驻复用**，`ClosePanel()` 只 `Hide()` 不 `Close()`；`Closed` 才是真正销毁；
- 启动后空闲优先级 `PrewarmPreview()`：只建 HWND 不显示，第一次悬停零建窗成本；
- 去掉 `SizeToContent`，`Open()` 里 `RootBorder.Measure(∞)` 后显式写 `Width/Height`，
  位置立即算出，不再等 `Loaded` 跳位。

实测 `预览面板 open 耗时`：首次 86.5ms → **复用后 7~8ms**。
另把默认悬停延迟 500ms → 250ms（`PreviewHoverDelayMs`），更接近 macOS 的手感。

### 10.4 自动隐藏抖动：Dock 只闪一下、停不到手边

排查时发现 `Show()` 后约 450ms 必然 `Hide()`，表现为 Dock 反复"露一条缝"。
三层原因：

| 原因 | 修法 |
| --- | --- |
| 2px 热区是顶层窗口，滑入后仍压在光标下面，Dock 认为"指针不在自己身上" | `Show()` 里**立刻** `SyncHotZone()` 撤掉热区（原来要等滑入完成 220ms） |
| `hideDelayMs = 0` + 没有保护期，一条隐藏请求立刻生效 | 新增 `ShowGraceMs = 450`：滑入后 450ms 内忽略非强制隐藏，延后重判 |
| 窗口被"移到"静止光标下时 Windows 不补发 `WM_MOUSEMOVE`，WPF 的 `IsMouseOver` 一直是 false | `IsPointerOverDock` 补几何判定 `IsCursorInsideDock()`；再加 160ms 光标在场巡检，进入/离开都靠几何判定驱动 `PointerEntered/PointerLeft` |

修后实测：贴底停留 2.4s 稳定在 `top=1189`（完全滑入，无抖动），移开后 0.6s 内滑出到 `top=1409`。

### 10.5 滑入动画冻结在"只露一条缝"

`AnimationEngine` 只有 `CompositionTarget.Rendering` 一个时间源，而 Dock 滑入时窗口几乎整个在
屏幕外，合成器不一定出帧 → 动画停在半路（实测停在 218 中的 198）。
新增**兜底节拍器**：仅在动画期间运行的 15ms `DispatcherTimer`，与合成器共用同一份状态；
两路都触发时按"距上次推进不足 6ms 就丢弃"去重，不会跑成两倍速。

### 10.6 图标观感（和 macOS 的差距）

| 问题 | 处理 |
| --- | --- |
| 名称标签画在图标**内部**，一条深色条压住约 1/3 图标高度 | 移到图标**正上方**的圆角浮签；`tooltip` 模式下悬停即现（不再依赖 ~1s 延迟的系统 ToolTip） |
| 系统区字形纯白，在浅色胶囊上隐形 | 半透明深色描边 + 保留白色填充，深浅背景都能读出形状 |
| 悬停放大不明显 | 实测生效（`magnifyScale=1.7`，邻域高斯衰减），截图可见中心图标明显更大 |
| 用户配置 `iconLabelMode=always` 导致整排都是标签，很吵 | 该机配置改为 `tooltip`（设置 → 名称显示可随时改回） |
