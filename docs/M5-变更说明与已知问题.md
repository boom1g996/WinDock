## 1. 这一批做了什么

产品从「macOS 式 Dock」转向「Windows 任务栏替代」。本批交付**三段式全宽任务栏骨架**，旧 Dock 行为一行不删、通过配置回落。

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 双布局模式（`dock` / `toolbar`） | ✅ | `dock.mode`，默认 `toolbar` |
| 宽度策略（`fill` / `fit`） | ✅ | `dock.widthMode`，默认 `fill` |
| 左段：启动台 / 显示器 / 当前窗口缩略图 | ✅ | 三件全部可点 |
| 中段：时钟 + 日期 | ✅ | 对齐整分触发，格式可配 |
| 右段：应用图标 + 分隔线 + 设置齿轮 | ✅ | 复用既有 `IconsPanel` |
| 启动台面板（网格 + 搜索） | ✅ | 常驻复用、分批填充 |
| 原生任务栏接管（隐藏 / 恢复 / 崩溃还原） | ✅ | 复用 `general.taskbarMode`，无新开关 |
| 设置面板「任务栏」分组 | ✅ | 9 项可热更，`dock` 模式下自动置灰 |

> **启动台原先排在 M5-2**，因用户在范围确认时点名要「任务栏骨架 + 启动台」，本批一并提前交付，M5-2 只剩托盘镜像与日历/通知面板。

## 2. 实现要点

### 2.1 一套控件，两种布局（不做两份副本）

WPF 元素只能有一个父容器，因此**切换布局时搬的是父容器，不是控件**：

```csharp
var parent = IconsPanel.Parent as Panel;
if (toolbar)
{
    parent?.Children.Remove(IconsPanel);
    ToolbarRight.Children.Insert(0, IconsPanel);   // 插在分隔线之前
    ToolbarGrid.Visibility = Visibility.Visible;
}
else
{
    parent?.Children.Remove(IconsPanel);
    Body.Children.Add(IconsPanel);
    ToolbarGrid.Visibility = Visibility.Collapsed;
}
```

早期版本试过「准备两份 IconsPanel，用 Visibility 切换」，结果是配置热更时整棵树重建、图标闪一帧、拖拽控制器缓存的引用全部失效。搬父容器方案下图标实例不变，拖拽/悬停/预览句柄全部继续有效。

### 2.2 三段布局的尺寸链

三列 `*` / `Auto` / `*`：左右两列等分剩余空间、中列取内容宽，**时钟因此严格居中**（不依赖任何魔法数字）。

| 量 | 取值 |
| --- | --- |
| 窗口宽 | `work.Width − 2 × ToolbarMargin`（`fill`）或内容宽（`fit`） |
| 窗口高 | `max(ToolbarHeight, Capsule 内容高)` |
| 胶囊对齐 | toolbar 下必须 `HorizontalAlignment = Stretch` |
| 定位 | `Left = work.Left + ToolbarMargin − Root.Margin.Left`，贴工作区底边 |

`Stretch` 是修出来的结论：`Center` + 按内容自适应时，窗口 1795 宽、胶囊只有 1047 宽，玻璃只画了中间一截（见 K-31）。

### 2.3 时钟对齐整分

1 秒轮询 24 小时要唤醒 86400 次，对「空闲 CPU ≤0.3%」的预算是纯浪费。改为每次触发后计算「距下一整分的毫秒数 + 120ms 余量」再排下一次，误差不累积。格式串非法时 `FormatSafe` 回落到默认格式，不抛异常。

### 2.4 当前窗口缩略图独立成服务

`ActiveThumbnailService` 与既有 `PreviewService` **刻意分开**：预览面板是「一组句柄、鼠标移开全注销」，任务栏缩略图是「一个句柄、跟着前台窗口走的长生命周期对象」。合在一起会让 `Hide()` 语义互相打断（预览一关，任务栏缩略图跟着黑）。

- 监听 `EVENT_SYSTEM_FOREGROUND`（`WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS`）；
- 排除 Shell 类窗口（`Progman` / `WorkerW` / `Shell_TrayWnd` / `Shell_SecondaryTrayWnd` / `NotifyIconOverflowWindow` / `Windows.UI.Core.CoreWindow`）、自身进程、最小化窗口；
- DWM 缩略图**直接合成到宿主窗口最上层**，WPF 的圆角与 Z 序都管不住 → 目标矩形用 `TransformToAncestor` + DPI 换算逐像素对准 `ActiveThumbHost`，内缩 1px 避开描边。

### 2.5 亮背景下的彻底隐形（K-32）

浅色主题的 tint 接近白色，遇到白色壁纸或白色窗口时，**整条任务栏与背景只差 5 个色阶**（截图采样实证），玻璃、边框、字形、时钟全部消失。

修法：抓屏后采样平均亮度（48 行 × 每 32px，`0.2126R + 0.7152G + 0.0722B`）：

```csharp
double luma = SampleLuminance(blurred);
bool lightBackdrop = luma > 0.55;
double tintAlpha = lightBackdrop ? Math.Max(_tintAlpha, 0.42) : _tintAlpha;
TintLayer.Background = new SolidColorBrush(ResolveCapsuleTint(tintAlpha, forceDark: lightBackdrop));
Capsule.BorderBrush = lightBackdrop ? new SolidColorBrush(Color.FromArgb(0x33, 0, 0, 0)) : ParseBorderBrush(...);
ApplyBarForeground(lightBackdrop);   // 亮背景强制深色字形
```

### 2.6 启动台

- 来源：`CommonStartMenu\Programs` + `StartMenu\Programs` 的 `*.lnk`，后台线程枚举、按名去重排序；
- 填充：**分批 18 个/拍**，`_feedToken` 作废旧批次（快速关开不会串数据）；
- 生命周期：常驻复用，`ClosePanel()` 只 `Hide()`；`Deactivated` / `Esc` 关闭；
- 点击：走既有 `IAppLauncher.Launch`，与 pinned 项同一条路。

### 3.2 三段布局数值自证

`DockHost.exe --dump-layout=<nonce>`（`mode=toolbar`，125% DPI，主屏 1792×1120 逻辑）：

```
win=(-1,1233,1795,100) dip=(-1,986) hwnd=(-1,1233,2243,1359) count=10
w=1795.2 h=100.8 root=(1752.8x60.8) cap=(1752.8x60.0) panel=(680.8x43.2) children=11
segs=(41,61,228x55),(1083,61,79x55),(1275,61,927x54)
```

换算回 DIP 与胶囊坐标（胶囊中心 = 21.2 + 1752.8/2 = **897.6**）：

| 段 | 起点 x | 宽 | 中心 | 结论 |
| --- | --- | --- | --- | --- |
| 左（启动台/显示器/缩略图） | 32.8 | 182.4 | — | 贴左（胶囊左内边 29.2 + padding 8） |
| 中（时钟 + 日期） | 866.4 | 63.2 | **898.0** | 与胶囊中心 897.6 相差 0.4 DIP，居中成立 |
| 右（图标 + 分隔线 + 齿轮） | 1020 | 741.6 | — | 右端 1761.6，贴右 |

右段 741.6 = `panel 680.8` + 分隔线 + 40 齿轮 + 间距，与 `children=11`（10 图标 + 分隔线 + 齿轮的视觉计数）自洽。

### 3.3 空载与启动台开销实测（解锁后补测）

`toolbar` + 常显（`autoHide=false`，最严场景，玻璃持续抓屏）、光标移出任务栏：

| 场景 | CPU（单核口径，10s 窗口） | 私有字节 | GDI | 句柄 |
| --- | --- | --- | --- | --- |
| 空闲（预热后） | mean **0.104~0.208%**，max 0.625% | 210MB 稳定 | 24 | 630 |
| 启动台**首次**打开 | 峰值 **41.9~47.2%**（后台提取 124 个图标），5s 后回落 0.6~1.9% | 210 → 266MB | 24 → 29 | 634 → 661 |
| 启动台**二次**打开 | mean **1.95%**，max 4.1% | 253MB（不回落，磁贴常驻） | 30 | 654 |
| 关闭面板后 | mean **0.104~0.312%** | 248~252MB | 29 | 651 |

**AC-20 结论**：空闲 0.104~0.208% **达标**（≤0.3%），比 `dock` 形态的 0.212% 略好——全宽窗口面积 +3.3× 但抓屏是同一套节流逻辑，空闲时并不持续抓。

### 3.4 这一轮修掉的性能回归（K-41）

首次实测时启动台一打开就把进程打到 **82~95% CPU 持续 5~10 秒**，GDI +42、句柄 +142。三个叠加原因与修法：

| 原因 | 修法 | 效果 |
| --- | --- | --- |
| `AllowsTransparency=true` 的分层窗口上挂了 `DropShadowEffect BlurRadius=30` → **整窗软件渲染**，且任意子元素变化都重算整窗高斯模糊（124 磁贴分 7 批 = 7 次全窗模糊） | 阴影改成三层纯色 `Border` 叠出来（`#0A000000` / `#18000000` / 主 Border），彻底不用 `Effect` | GDI 增量 +42 → **+5**；句柄 +142 → **+27** |
| `CreateTile` 里同步调 Shell 图标提取（124 个 ≈ 5 秒，全在 UI 线程） | 磁贴只做纯 WPF 对象构造，图标甩后台线程逐个提取，完成一个用 `Dispatcher` 点亮一个（`BitmapSource` 已 `Freeze`，可跨线程） | 面板立即可见，UI 线程不阻塞；CPU 峰值 95% → 42% |
| 每次 `Open()` 都 `Clear()` + 重建全部磁贴 | `_renderedEntries` 引用相同则直接复用 | 二次打开 mean 1.95% |

**残留**：首次打开仍有 41~47% 的峰值，是 124 个 `.lnk` 的 Shell 图标提取本身（有磁盘缓存后二次就快）。若后续要压掉，需引入「可见区优先 + 滚动懒加载」的虚拟化网格。

### 3.5 视觉验收（已解锁目视）

1920×1080 @100% DPI，三段全部就位：左段九宫格 + 显示器 + 当前窗口缩略图，中段 `12:10` / `2026/11/11` 居中，右段 10 个应用图标 + 分隔线 + 齿轮；玻璃条左右留白对称、圆角完整、无裁切。

## 5. 配置变更

`dock` 段新增字段（缺省值即产品默认）：

```jsonc
"dock": {
  "mode": "toolbar",            // dock | toolbar（本批默认改为 toolbar）
  "widthMode": "fill",          // fill | fit
  "toolbarHeight": 58,          // ConfigRanges 44~96
  "toolbarMargin": 20,          // ConfigRanges 0~200
  "showClock": true,
  "clockFormat": "HH:mm",
  "dateFormat": "yyyy/MM/dd",
  "showLauncher": true,
  "showMonitorButton": true,
  "showActiveThumbnail": true
}
```

- 非法 `mode` / `widthMode` 回落 `toolbar` / `fill`，越界数值 Clamp，均写 warning 进日志；
- **没有**新增「接管任务栏」开关 —— 复用既有 `general.taskbarMode`（`beautify` / `coexist` / `replace`），设置面板两个入口双向同步同一字段，避免两个开关语义重叠。

## 6. 升级注意

老配置文件（无 `dock.mode`）升级后**默认进入 toolbar 形态**。想回到原 Dock 外观：设置 → 任务栏 → 形态选「Dock」。
