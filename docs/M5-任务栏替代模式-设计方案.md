# M5 设计方案：从「Dock」转向「任务栏替代」

> 触发：2026-11-11 用户提供 AirDeck 1.3.3 三张宣传图，明确目标 ——
> 「不一定要按照 macOS 的样式来做，我想做的是一个能够替代 Win 任务栏的应用」。
> 本文是 M5 的设计说明与任务拆解，**确认后才写产品代码**（需求文档第 14 章约定）。

---

## 1. 目标形态

一条**横贯工作区底部**的玻璃任务栏，分三段，上方按需浮出功能面板。

```
┌────────────────────────────────────────────────────────────────────────────┐
│ ┌──┐┌──┐┌────┐        ┌────────────────┐        ┌─┐┌─┐┌─┐┌─┐   ┌──┐      │
│ │▦ ││🖥 ││ ▣  │        │     18:09      │        │✓││抖││微││盾│   │⚙ │      │
│ └──┘└──┘└────┘        │   2026/11/08   │        └─┘└─┘└─┘└─┘   └──┘      │
│  启动台 显示器 当前窗口        时钟 + 日期              系统托盘镜像    设置     │
└────────────────────────────────────────────────────────────────────────────┘
```

| 区段 | 内容 | 交互 |
| --- | --- | --- |
| 左 · 启动台 | 九宫格图标 | 点击 → 应用网格面板（浮在任务栏上方） |
| 左 · 显示器 | 显示器图标（多屏时带编号） | 点击 → 切换 Dock 所在屏 / 多屏列表 |
| 左 · 当前窗口 | 前台窗口 DWM 实时缩略图（约 72×40） | 点击 → 还原/切换该窗口；多窗口时开预览 |
| 中 · 时钟 | `HH:mm` 大字 + `yyyy/MM/dd` 小字 | 点击 → 日历 + 通知面板 |
| 右 · 托盘 | 第三方应用托盘图标（镜像原生托盘） | 左键 → 该应用托盘菜单；右键 → 原生命令 |
| 右 · 设置 | 齿轮 | 点击 → 设置中心 |

**保留的能力**：现有 pinned / running 图标、悬停放大、DWM 预览面板、拖拽排序、自动隐藏、热区、看门狗、无边框玻璃。

**新增的开关**：任务栏布局模式（`dock` 自适应 / `toolbar` 任务栏）、原生任务栏接管。

## 3. 分期与验收

### M5-1 任务栏骨架（本次开工）

| # | 任务 | 验收 |
| --- | --- | --- |
| 1 | `DockLayoutConfig.Mode` = `dock` / `toolbar`；三段 Grid 结构 | 切换模式后布局正确，旧配置默认 `dock` 不变 |
| 2 | 宽度策略：`fill`（工作区宽 − 留白）/ `fit`（按内容） | 两种都能量到正确矩形，不出现 K-24 那种"窄条" |
| 3 | 时钟组件：对齐整分的定时器 + 可配格式 | 空闲 CPU 增量 < 0.02%；跨分钟自动跳 |
| 4 | 启动台按钮 / 显示器按钮 / 设置齿轮（先占位可点） | 点击有响应，不崩 |
| 5 | 当前窗口实时缩略图 | 前台切换后 300ms 内更新；无窗口时显示占位 |
| 6 | 原生任务栏接管开关（隐藏/恢复 + 崩溃自动还原） | 强杀进程后重启能恢复原生任务栏 |
| 7 | 设置面板新增「任务栏」分组 | 三项开关可热更 |

**出口**：构建 0 警告 0 错误、自检全绿、可运行自包含包、`toolbar` 模式下日常可用。

### M5-2 面板与托盘

- 启动台面板（网格 6 列 + 搜索 + 滚动，毛玻璃）
- 系统托盘镜像（UIA，见 §4）
- 日历 / 通知面板

### M5-3 系统能力

- 控制中心：WiFi / 蓝牙 / 音量 / 亮度
- 设置中心改左侧导航（通用 / 外观 / 任务栏 / 组件 / 动效 / 应用 / 账户）

### M5-4 装饰

- 桌面组件（天气 / 媒体播放 / 性能）
- 玻璃雨特效

## 4. 技术风险（已实机探测）

### ① 接管系统托盘 —— 老路已死

2026-11-11 在 Build 26200 实测 `Shell_TrayWnd` 子窗口树：

```
Shell_TrayWnd (0,1360,2240,40)          ← 本机任务栏现在在**底部**
  0x10320 Windows.UI.Composition.DesktopWindowContentBridge   ← XAML 岛屿
  0x101ca TrayNotifyWnd (1904,1360,336,40)
  0x101d0 ReBarWindow32 → MSTaskSwWClass → MSTaskListWClass
```

**没有 `ToolbarWindow32`**，`NotifyIconOverflowWindow` 也不存在。也就是说：

- 老工具（TrafficMonitor 那一代）用的「跨进程 `TB_GETBUTTON` + `VirtualAllocEx` + `ReadProcessMemory` 读 `TRAYDATA`」**在本机行不通**；
- 只剩 UI Automation 一条路：从 `TrayNotifyWnd` 的 UIA 子树逐个读按钮元素的名称与矩形，点击时对元素 `Invoke` / 模拟点击。
- 代价：首次枚举 100~300ms、随系统更新可能失效、无法拿到"更多"菜单里的隐藏项。
- **结论**：M5-2 先写一个 20 行的 UIA 探测，能稳定枚举到 ≥1 个图标才继续，否则退化成「只显示我们自己的托盘图标」。

### ② 隐藏原生任务栏的连带影响

`Win+D` / `Win+Tab` / `Alt+Tab` / 托盘溢出面板 全部依赖 `Shell_TrayWnd`。接管后需要：

- 开机/重启 `explorer` 后重新隐藏（已有 `TaskbarRecreated` 事件钩子）；
- 全屏应用期间不重复隐藏；
- 崩溃/强杀后下次启动自动恢复（已有快照机制，需补一条 M5 自检）。

### ③ 全宽窗口的性能

窗口从 672px 变 2240px，`GlassBackgroundService` 的抓屏面积约 +3.3×。
需要在 M5-1 里复测：空闲 CPU（AC-20 ≤0.3%）、帧率（AC-21 ≥55 FPS）。
必要时给玻璃抓屏加"仅脏区重抓 + 最长 500ms 节流"。

## 5. 配置新增（草案）

```jsonc
"dock": {
  "mode": "toolbar",            // dock | toolbar
  "widthMode": "fill",          // fill | fit
  "toolbarHeight": 60,
  "toolbarMargin": 12,          // 距离工作区左右/底边留白
  "showClock": true,
  "clockFormat": "HH:mm",
  "dateFormat": "yyyy/MM/dd",
  "showLauncher": true,
  "showMonitorButton": true,
  "showActiveThumbnail": true,
  "showTrayMirror": true
},
"general": {
  "takeOverTaskbar": false      // 隐藏原生任务栏
}
```

## 6. 明确不做

- 不做 Windows 10 适配（沿用 M1 决策）。
- 不修改系统级设置（只动 HKCU，已有约束）。
- 不引入 NuGet 依赖（UIA 走 `UIAutomationClient` 系统程序集，`DwmRegisterThumbnail` 已是 P/Invoke）。
- 不模仿 macOS 的"图标从胶囊里长出来"动画（成本高、非目标形态）。
